# S9.5 — Fold the code quality standard into the CI gate

**Story:** SPRIN-50, under epic SPRIN-44 (E9 Code quality standard)
**Date:** 2026-07-28
**Branch:** `feature/sprin-50-standard-gates`

## Context

E9 adopted the shared code-quality standard as a **report**, not a gate
(`da55dea`, #42). The audit's sequencing (`docs/standards-audit-2026-07-25.md`,
"Sequencing") has four steps; three are done:

1. Report exists, non-gating — done.
2. Pass A, formatting and safe fixes — done.
3. Pass B, extraction and duplication — done across S9.1–S9.4. Complexity went
   7 → 0 findings; prod-to-prod duplication went 11 clones → 3, all three inside
   files any gate must exclude.
4. **Fold the rules into `lint`/`verify` so the standard gates.** This story.

Both bars the sequencing set are met, so this change should be a switch-flip
rather than a cleanup: `lint:standards` reports **0 findings** today, and
production duplication measures **0 clones**.

## What "gating" means here

`npm run verify` is the required status check on `main` and there are no bypass
actors, so anything added to `verify` blocks every merge — including the merge
that would fix it. That is the whole point, and also the whole risk. The design
below is shaped by one rule: **a gate that cannot fail is worse than no gate**,
because it reports success while verifying nothing. Every decision that follows
is either about making the gate fire, or about proving that it does.

## Decisions

### D1 — Merge the standards config into `eslint.config.js`; delete the second config

`eslint.standards.config.js` is folded into `eslint.config.js` and deleted, and
the `lint:standards` script is retired. `npm run lint` becomes the single
enforcement point, so `verify` gates the thresholds with **no change to
`verify.yml`**.

Rejected: keeping both files and running `npm run lint && npm run lint:standards`
inside `verify`. It lints the whole repo twice and leaves two configs whose
`ignores`, `extends` and `languageOptions` blocks are already byte-identical and
would drift.

The merge is mechanical but has four override blocks that must survive verbatim,
each traceable to an ADR:

| Override | Scope | ADR |
|---|---|---|
| `max-lines-per-function` off | `**/*.tsx` | 0001 |
| `max-lines-per-function`, `max-lines`, `sonarjs/cognitive-complexity` off | test files, `src/test/**`, `e2e/**` | 0002 |
| `max-lines-per-function`, `max-lines`, `complexity` off | `src/components/ui/**` (vendored shadcn) | — |
| `max-lines` off | `src/lib/database.types.ts` (generated) | — |

The existing `src/components/ui/**` block in `eslint.config.js` (which turns off
`react-refresh/only-export-components`) merges with the standards config's block
for the same path, into one.

### D2 — The duplication gate is a script in `scripts/`, not a raw CLI call

`scripts/check-duplication.mjs`, following `scripts/check-bundle.mjs` exactly:
a module with a **pure, exported evaluation function** plus a `main()` guarded by
the `import.meta.url === process.argv[1]` check, and a sibling
`scripts/check-duplication.test.mjs`. That existing pair is the repo's convention
for "a check that gates the build and is itself tested".

A bare `jscpd --threshold 3` in `package.json` cannot satisfy AC5 (see D5): it
exits 0 on an empty scan. The script exists to make the check falsifiable.

Structure:

- `runJscpd({ paths, ignore, minLines, minTokens, reportDir })` — spawns the
  jscpd CLI with the JSON reporter and returns the parsed report.
- `evaluateReport(report, limits)` — **pure**; takes the report object, returns an
  array of violations. This is the seam the unit tests drive with synthetic
  reports, mirroring `findPrivilegedCredentials`.
- `main()` — wires them over the production scope, prints
  `check-duplication: N files / M lines scanned, X% duplicated`, exits 1 on any
  violation.

jscpd 5.x is a **native-binary package** (`jscpd-linux-x64-gnu` and five other
optional platform binaries) with **zero JavaScript dependencies**. There is no
`@jscpd/core` JS API to import — verified, not assumed. Spawning the CLI is the
only option, and the zero-dependency tree means the gate adds no vulnerability
surface (the repo's 6 existing `npm audit` findings are react-router's and
predate this change).

### D3 — Scope: production code only, with two exclusions, not four

The gate scans `src`, ignoring:

- `**/*.test.ts`, `**/*.test.tsx`, `**/*.spec.ts`, `src/test/**` — tests.
- `src/lib/database.types.ts` — generated from the live schema.
- `src/index.css` — the Tailwind `@theme` blocks are declarative repetition.

Tests are excluded on ADR 0002's existing principle (thresholds measure
production code). The number behind that: a naive `npx jscpd src` reports **86
clones, 870/16,429 lines = 5.30%**, and essentially all of it is arrange-blocks
in integration suites. Gating that would force test suites to be restructured to
satisfy a duplication metric, which ADR 0002 already rejected for size.

**`src/components/ui/**` is deliberately NOT excluded**, even though both ESLint
configs exempt vendored shadcn from the size thresholds. Measured: including it
adds 9 files / 643 lines and still yields **0 clones**. An exclusion that buys
nothing today is an exclusion nobody will revisit when it starts hiding
something. If a future `shadcn add` ever trips it, adding the exclusion is one
line plus an ADR — a deliberate act, not a pre-granted one.

`e2e/**` is out of scope (tests). `api/**` is out of scope: `ruff check api` runs
in `api.yml`, which is deliberately non-required and must never fold into
`verify`.

### D4 — Thresholds are stated explicitly, never inherited

`maxPercentage: 3` (the standard's bar), and `minLines: 5` / `minTokens: 50`
stated **explicitly** rather than left to jscpd's defaults, even where the values
match today's defaults.

This is the direct lesson of the ruff incident: `api/pyproject.toml` set no
`select`, so it inherited whatever the installed version called "default", and a
version bump reddened CI on unchanged code. A duplication tool's sensitivity
knobs are the same hazard — if `minTokens` widens in a future release, the gate's
verdict changes with no commit. Stating them pins the gate's meaning to the repo.

`jscpd` is pinned **exactly** (`"jscpd": "5.0.14"`, no caret) for the same
reason.

**`eslint` and `eslint-plugin-sonarjs` are deliberately left on caret ranges.**
This looks inconsistent and is a considered call: CI installs with `npm ci`,
which installs the committed lockfile verbatim, so **the lockfile — not the range
in `package.json` — is this repo's operative version pin**, and it already fixes
sonarjs at 4.2.0. The ruff drift was possible only because pip had no lockfile.
Pinning the whole lint toolchain exactly is a reasonable, separate, mechanical
change; folding it into a CI-gate story would mix a behaviour change with a
dependency change in one diff.

### D5 — The empty-scan guard is the load-bearing part

Verified on this repo, today:

```
npx jscpd src --ignore "" --threshold 3   →  0 files, 0 lines, 0.00%, exit 0
```

A misconfigured ignore glob makes jscpd scan **nothing**, report a perfect score,
and exit successfully. That is not hypothetical — the E9 baseline itself once
recorded `0(0.00%) in 0 files` from bad `--format` arguments while a plain re-run
of the same tree found 78 clones.

So `evaluateReport` fails on a **floor**, not just a percentage:

- `statistics.total.sources` must be **≥ 40** (today: 64).
- `statistics.total.lines` must be **≥ 3000** (today: 5,822).

Both are tripwires, not targets: they exist to catch a broken glob, and they must
never be read as a code-size goal. The failure message says so, and says the
ignore patterns are the first place to look.

Rejected alternative: having the script glob the production file set itself with
Node and compare counts against jscpd's. It cross-checks two independent glob
implementations, which is genuinely stronger, but it produces spurious mismatches
whenever jscpd declines a file for format reasons, and a noisy guard gets
weakened. A dumb floor that can only ever be too lenient beats a clever one that
gets disabled.

### D6 — Wiring into `verify`

```
"lint:duplication": "node scripts/check-duplication.mjs",
"verify": "npm run lint && npm run lint:duplication && npm run format:check && npm run build && npm test"
```

Duplication runs second: it is fast (~7ms of analysis) and its failures are
cheap to read, so it belongs with the other static checks and well before the
build and the live test suites. `verify.yml` is untouched — it calls
`npm run verify`, and there is exactly one definition of that.

### D7 — The gate is proved by tests that fail when it breaks, not by assertion

Three ACs say "proved red-then-green". The durable form of that proof is a test
that fails if the gate stops working. This project has form here: `check-bundle`
was positive-controlled with a planted `sb_secret_` canary, and a 48-agent pass
once found a broken `check-bundle` control that four conventional reviews missed.

**`eslint.config.test.mjs`** (new, repo root, beside its subject) lints source
strings through the real config via ESLint's Node API and asserts:

- a 35-line function in a `.ts` file under `src/lib/` **errors** on
  `max-lines-per-function`;
- the same function in a `.tsx` file does **not** — pinning ADR 0001's boundary
  from both sides.

Asserting **opposite outcomes** across two real paths is deliberate: a required
rule that is simply on everywhere, or simply off everywhere, fails one of the two
assertions. A single-sided test would pass under a blanket setting that silently
retires the ADR — the same failure the S9.4 `passwordAutoComplete` prop showed,
where a required union type caught omission and typos but not a swap of two
valid values, and only asserting opposite values on two real call sites closed
it.

**`scripts/check-duplication.test.mjs`** covers both layers:

- `evaluateReport` against synthetic reports — over-threshold, zero-sources,
  below-floor, and clean.
- One **end-to-end** case: run the real checker against a fixture directory
  holding a planted clone and assert it fails, and against a clean fixture and
  assert it passes. The pure-function tests alone cannot catch "the globs are
  wrong, so jscpd never sees the clone" — that is exactly the vacuous-test shape
  this project keeps finding. This requires the checker to take its target path
  as a parameter, which it should anyway.

Both new files are collected by Vitest (its default include glob covers `.mjs`,
which is why `scripts/check-bundle.test.mjs` already counts). **The tripwire
counts therefore move: full 52 → 54, unit 45 → 47, gap unchanged at 7.**
`CLAUDE.md` records those as a timestamped observation and must be updated.

### D8 — Documentation

- **New ADR 0005** — the duplication gate: scope, the two exclusions, why
  vendored shadcn is *not* excluded, the explicit sensitivity settings, and the
  empty-scan floor.
- **ADR 0002 addendum** — its "production code, not test files" principle now
  also governs duplication scope.
- **ADR 0003 addendum** — the config it names has been merged into
  `eslint.config.js`. Its accepted consequence, "the numbers can drift from the
  standard silently — accepted for a non-gating report", no longer has its
  justification: the report now gates. The decision (restate rather than import)
  stands, since the shared config is still unpublished; the addendum records that
  the drift risk is now carried by a gate.
- **`CLAUDE.md`** — the tripwire counts, and a line stating that `verify` now
  enforces the standard.
- **`docs/standards-audit-2026-07-25.md`** — a closing status note that Step 4
  landed, retiring "the only remaining E9 work".
- Historical specs and plans under `docs/superpowers/` that mention
  `lint:standards` are **left as written**. They are records of what was true
  when they were written; the repo's convention for superseded records is an
  addendum, not a rewrite.

## Acceptance criteria

- **AC1** `npm run verify` green on a clean tree; test-file gap to `test:unit`
  still 7; 0 skipped.
- **AC2** A 35-line function in `src/lib/` turns `npm run lint` red — and the
  same function in a `.tsx` file does not. Proved by `eslint.config.test.mjs`.
- **AC3** A planted duplicated block in production code turns
  `lint:duplication` red. Proved end-to-end by `check-duplication.test.mjs`.
- **AC4** Neither `src/lib/database.types.ts` nor `src/index.css` can fail the
  duplication gate.
- **AC5** A scan that analyses zero files **fails**, and its message names the
  ignore patterns as the likely cause.
- **AC6** `verify.yml`, `e2e.yml`, `api.yml` byte-unchanged.
- **AC7** No live reference to `lint:standards` or `eslint.standards.config.js`
  outside historical records; ADRs updated per D8.

## Risks

- **The gate blocks the merge that would fix it.** Mitigated by the switch-flip
  premise: both underlying counts are 0 before the change, verified again in
  step 6 of the build.
- **A native binary now sits in the required gate.** `npm ci` fetches
  `jscpd-linux-x64-gnu` on the runner; dev and CI are both linux-x64. If the
  binary is ever unavailable the script fails loudly (non-zero spawn), which
  fails closed — correct, if noisy.
- **The floor decays.** Nobody will raise it as the repo grows. Accepted: it can
  only ever become more lenient than the day it was set, and its job is catching
  a broken glob, not tracking growth.
