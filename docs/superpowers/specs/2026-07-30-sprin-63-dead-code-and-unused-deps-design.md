# SPRIN-63 — Remove dead code and unused dependencies from the source tree

**Date:** 2026-07-30
**Story:** SPRIN-63, the first slice of epic **SPRIN-57** "Pivot phase 2 — remove redundant
files and code".
**Constraint from the epic:** *"No behaviour change. This epic removes only what is already
dead."* Every item below is held to that.

---

## Scope

The **source tree and its configuration**, plus `package.json`. Documentation deletions —
`docs/sprintboard.md`, `docs/standards-audit-2026-07-25.md`, and the phase-1
backlog/traceability pair — are deliberately **held back for a later slice**, because removing
them also edits CLAUDE.md's *Key files* section and that is a different review with a different
risk. Mixing "delete a 5KB asset" with "delete the backlog the board replaced" in one PR would
make both harder to judge.

## How the candidate list was produced

Two passes, because one was not enough.

**Pass 1 — knip**, run via `npx` rather than installed (installing a tool to find unused
installs is its own joke). It reported **0 unused files, 0 unused dependencies, 11 unused
exports, 14 unused exported types**. Most of those 25 are protected or generated and were
discarded by hand: `src/lib/domain.ts` is on the epic's PROTECTED list and its `Assert*` types
are compile-time exhaustiveness guards that are *unused by design* — being unused is their
entire function; `src/lib/database.types.ts` is generated by Supabase; `src/components/ui/**`
is vendored verbatim from the shadcn registry and trimming it diverges from the source a future
`shadcn add` restores from.

**Pass 2 — a five-lens adversarial sweep**, because knip only sees unused *exports*. Five
independent read-only agents swept for unreachable branches, duplicated domain rules, stale
configuration, rationale deferring to deleted files, and orphaned non-TypeScript assets. Each
lens's candidates then went to a **refuter** briefed to find the consumer the finder missed and
to default to "not dead" under uncertainty. **25 candidates, 10 survived, 15 were killed.**

### The refutation was the point, not the ceremony

The sweep's single most valuable output was **killing a candidate this document's author had
already written into the Jira issue as fact**: that `shadcn` sits in `dependencies` while being
a CLI imported by nothing. It is not. `src/index.css:3` is `@import 'shadcn/tailwind.css'`,
resolved through the package's exports map, so **removing it fails `npm run build` outright,
inside the required gate.** A JS/TS dependency scanner cannot see this because it never opens a
`.css` file — which is exactly why the second pass existed. Verified independently before
accepting.

*Corrected during review, and the correction is instructive.* The first version of this
paragraph offered a second piece of evidence: that the package's `@utility` output was
"demonstrably in the built CSS" because certain animation utility names appeared in `dist/`.
A reviewer measured it and that was wrong — on `origin/main` only the unconditional
`@property` registrations ship, with no rule body at all, so the observation showed the
utility was *unused*, not in use. It was also **self-confirming**: this very document
mentioning those names is what compiled them into `dist/` (see the build note below), so a
future session re-running the grep would have "verified" the claim against evidence the
document itself manufactured. The import is the load-bearing argument; the grep was noise.

The other 14 kills are recorded in the PR; two are worth naming here because they are the kind
of "obvious tidy-up" a future session will re-propose:

- **The `.dark` block and `@custom-variant dark` in `src/index.css` are NOT inert.** The custom
  variant is the *suppressor* that keeps Tailwind v4 from falling back to its built-in
  `prefers-color-scheme` dark variant. Deleting it does not remove the `dark:` utilities — it
  re-points 12 compiled rule groups at a media query that fires for every visitor whose OS is
  in dark mode, against a `:root` still declaring light tokens. A user-visible rendering
  change produced by "deleting unreachable CSS", and nothing in the suite would catch it:
  Playwright runs in the default light scheme and jsdom asserts no computed styles.
- **Three ADR/audit paragraphs that describe deleted machinery in the present tense stay as
  written.** This repo's convention for a superseded record is a dated addendum, not a rewrite
  — stated in a protected plan and demonstrated inside ADR 0002 itself, whose Decision section
  deliberately still disagrees with today's config. Rewriting them is not cleanup; it is
  destroying the record.

## Decisions

### 1. Three exports are narrowed, not deleted

`TicketDeliverablesEditor` (`src/routes/TicketEpicSection.tsx`), and `useTicketError` /
`TicketError` (`src/lib/ticket-commit.ts`) are each **used inside their own file**. The dead
thing is the `export` keyword — the public surface — not the implementation. Dropping the
keyword is a visibility narrowing with no behaviour change and no test impact (nothing outside
each file references them). Deleting the implementations would be a behaviour change and is
wrong.

### 2. `BacklogTab`'s vacuous conjunct is removed **and the branch is pinned**

`src/routes/BacklogTab.tsx:26` reads `if (ticketsPhase === 'loading' && backlog.length === 0)`.
The right conjunct can never be false when the left is true: `useTaggedRead`
(`src/lib/project-reads.ts:170-175`) derives `phase` and `items` from the *same* `current`
binding, so `loading` implies `current === null` implies `items === []`. Both routes that could
break that coupling are closed — `patchLoaded` refuses to patch a non-`loaded` state, and
`onRetry` bumps the nonce that is part of the tag, so a retry returns items to `[]` in the same
render it returns phase to `loading`. `git log -S` shows the conjunct was transcribed verbatim
from an unrun plan draft at S5.1 with no stated rationale. It was never designed; it was copied.

**The conjunct only is removed, never the branch.** `BoardTab.tsx:101` already guards on the
phase alone, so this converges the two tabs. Deleting the whole branch would let a loading read
fall through to *"Nothing in the backlog."* — a confident claim about work we have not seen,
which is the exact defect the `failed`-before-empty ordering below it exists to prevent.

**This item gets a new test, and the reason is narrower than the first draft of this section
claimed.** That draft said the loading branch "is currently pinned by nothing" — it observed
that `BacklogTab.test.tsx` never sets `ticketsPhase: 'loading'` (line 38 defaults every case
to `'loaded'`) and generalised from one file to the suite. A reviewer refuted it by grep:
`BoardTab.test.tsx:551` and `:556` render *this same component* through the same harness with
an empty, loading context, so **deleting the branch was already pinned** and would already
have gone red.

What is genuinely pinned by nothing is the **conjunct**. No test anywhere renders `BacklogTab`
with `ticketsPhase: 'loading'` *and* a non-empty backlog — the only state in which the two
guards differ — so removing it would go green whether it was right or wrong. That single gap
is what the new test closes, and the first draft of this work also added a second test that
merely restated `BoardTab.test.tsx:551`; it has been dropped rather than shipped as new
coverage. Adding a redundant test inside a PR about removing redundancy is not a small irony.

The surviving test must be *seen* to fail against a deliberately broken version, not merely
observed to pass.

### 3. `.prettierignore` loses `api/` and `*.sql`

`api/` was the deleted Python FastAPI service. It is not merely dead — it is a **latent false
exemption**. `.prettierignore` uses gitignore semantics, so bare `api/` matches a directory
named `api` at *any* depth. A future `src/api/` would be silently exempted from
`prettier --check .` inside the required `verify` gate. Removing it closes that.

`*.sql` is dead in a stronger sense than "no file matches": **Prettier ships no SQL parser and
none is installed**, so the line cannot affect any file, present or future. Its only current
target is already covered by the `docs/` rule on line 3.

### 4. Two tsconfig flags are removed where a compile proves them no-ops

- `allowArbitraryExtensions` in `tsconfig.app.json` — the only non-JS import in the tree is
  `src/main.tsx:4 import './index.css'`, resolved by the ambient `declare module '*.css'` from
  `vite/client`, not by this flag.
- `allowImportingTsExtensions` in `tsconfig.node.json` **and** `tsconfig.test.json`.

Both were confirmed by **compiling with the flag forced off**, not by grepping for absent
files, and both runs had positive controls: an intentionally misspelled flag errors `TS5025`,
and forcing the same flag off in `tsconfig.app.json` *does* fail with `TS5097`. That last
result is the useful one — **the app project's copy is load-bearing and stays.** The three
tsconfigs end up deliberately non-identical, and that asymmetry is now the documentation: the
flag is present exactly where a file imports with an explicit extension (`src/main.tsx:5`).

*Recorded risk, accepted:* `tsconfig.test.json`'s program is not confined to `src/` —
`src/test/supabase-clients.test.ts:281` dynamically imports `e2e/support/admin.ts`, so a future
e2e helper written with an explicit `.ts` specifier would land in a project that no longer
allows it. The failure mode is a compile error caught immediately by the gate and fixed by
dropping the extension. That is cheap, visible, and not worth keeping dead config for.

### 5. `public/icons.svg` is deleted

A 5,031-byte social-media icon sprite from the initial scaffold. Nothing in `src/`, `e2e/`,
`index.html`, the workflows, or the docs references it, and Vite copies it verbatim into
`dist/` on every build — dead bytes shipped to every visitor. The `check-bundle.mjs`
`MIN_SCANNED_FILES` floor is unaffected: `SCANNABLE` is `/\.(js|mjs|cjs|css|html|map)$/`, which
excludes `.svg`, so the scanned count moves by zero.

**The comment at `scripts/check-bundle.mjs:38-43` that names this file stays.** It is a
historical incident record and the rationale for `MIN_SCANNED_FILES` counting reads rather than
walks. It still reads correctly as history once the file is gone; tidying it away with the
asset would delete the reasoning behind a security control. `check-bundle.mjs` is on the
PROTECTED list and is not touched.

### 6. The `--chart-*` and `--sidebar*` tokens leave `src/index.css`

Twenty-six declarations — five chart colours and eight sidebar colours, each declared twice
(`:root` and `.dark`) plus their thirteen `@theme inline` mappings — for shadcn components this
project does not have. They are shipped in the built CSS and consumed by nothing: `var(--chart`
and `var(--sidebar` appear zero times in `dist/`, and no `bg-sidebar`/`text-chart-*`-style
utility exists anywhere in the Tailwind-scanned tree.

That search had to be repo-wide, not `src/`-wide, and the reason is a genuine trap worth
recording: **Tailwind v4 auto-source-detection scans the whole non-ignored tree, so a class
name appearing only in a markdown code fence generates real CSS.** `dark:text-amber-400` is in
the built stylesheet and exists nowhere in `src/` — it comes from a protected plan document.
Any future claim that a utility is unused must be checked against `docs/` too.

Restoration is automatic rather than manual: `components.json` sets `cssVariables: true` with
`css: src/index.css`, so `npx shadcn add sidebar` patches the tokens straight back.

### 7. `@vitest/coverage-v8` leaves `devDependencies`

Referenced by nothing: no `coverage` script, no `--coverage` flag in any workflow, and coverage
is not gated — the T7/80%-coverage question is closed.

**Corrected after measuring, because the first version of this section overstated the cost.**
The concern written here initially was that SPRIN-58 might be re-scoped to a coverage
measurement and want this back. It would not have to be: `@vitest/coverage-v8` is an
*optional peer dependency of vitest*, so it stays resolvable after the direct declaration is
removed. Verified rather than assumed — `npm ls` reports it under `vitest@4.1.10`, and
`npx vitest run <file> --coverage` still produces a report on this branch.

So the honest scope of this change is narrower than "removes a dependency": it stops
`package.json` **declaring** a package the project does not directly use, while the tool stays
available through vitest. Install weight does not move. That is still the right change — a
manifest should say what the project depends on — but it should not be sold as a saving.

### 8. Markdown is excluded from Tailwind's source scanning

**Added during review, after a reviewer measured the branch and found it shipping a *larger*
stylesheet than `main`.** This is the finding of the whole slice.

Tailwind v4's auto-source-detection scans the entire non-ignored tree. Writing a bare utility
name in prose therefore compiles a real rule into the production stylesheet — so **this very
design document was adding ~1.6 kB of dead CSS**: animation rules and a radius utility that
nothing in the app renders, emitted purely because the document discusses them. Measured:

| Tree | `dist/assets/*.css` |
|---|---|
| `origin/main` | 46,401 B |
| this branch, before the fix | 47,164 B |
| this branch, after `@source not '../**/*.md'` | **43,590 B** |

A "remove dead code" slice was shipping 763 bytes *more* CSS than the branch it deletes from.
Nothing in `npm run verify` could see it: jsdom computes no styles and Playwright runs the
default colour scheme.

The fix excludes `.md` from scanning rather than contorting the prose, because the alternative
does not scale — every future design document would have to avoid naming the classes it exists
to discuss, and one slip silently re-pollutes the bundle. Excluding markdown fixes the class of
problem. It also drops a pre-existing instance nobody had noticed: an amber text colour named
only in a protected planning document had been shipping in the production stylesheet for weeks.

**The trap bites CSS comments too**, and it bit this one: the first draft of the comment
explaining the exclusion *named the class it was warning about*, in `src/index.css` — which is
a stylesheet, not markdown, and so is still scanned. It compiled exactly the rule it was
documenting. The comment now describes utilities instead of spelling them.

## Explicitly declined

- **`shadcn`** — refuted above. It is a live CSS import. This entry exists so the next session
  does not re-propose it from the same reasoning.
- **The `preview` script** (`vite preview`). Unreferenced by any machine, but it is a human
  affordance in the same category as `test:watch` and `typecheck` — equally uninvoked by CI and
  equally worth keeping. It is also the only way to serve the real `dist/` that
  `check-bundle.mjs` inspects. Removing it saves one line and buys nothing.
- **`--radius-2xl`, `--radius-3xl`, `--radius-4xl`.** Unused today, but these are *overrides*
  of Tailwind's built-in radius scale, not definitions of it. Deleting them does not remove
  `rounded-2xl` — it silently re-points it at Tailwind's default instead of this project's
  `calc(var(--radius) * N)` scale. The failure mode is a silent value change for a future user
  of the class, so it is not a no-op and does not belong in a "no behaviour change" slice.
  They are part of a coherent scale, and the three siblings above them are in use.
- **All 15 killed findings**, itemised in the PR body.

## Verification

- `npm run verify` in full, run by hand — never a subset, and never `npx tsc --noEmit`, which
  checks zero files in this repo yet exits 0.
- **The test-file tripwire is the GAP, not the counts.** Re-derived on this branch before any
  change: `npm test` collects **51**, `test:unit` collects **44**, **GAP 7**. The new
  BacklogTab test is an assertion inside an existing file, so it adds no file and the GAP must
  still read 7 afterwards. A run collecting 44 means the live suites silently skipped and is a
  failure however green it looks.
- The `.svg` deletion is checked against `check-bundle.mjs`'s scanned-file floor, not assumed.
- A whole-branch adversarial review before the PR, briefed to **break** the changes rather than
  read them — with the BacklogTab test as its first target, since a test that cannot fail is
  worse than no test.
