**Why `setError` takes an explicit `ticketId`.** Every current call site captures the id *before* awaiting (`const id = ticket!.id`, or `current.id` inside `commit`). A `setError(message)` that read the *current* ticket id would change behaviour: an error raised by a save that resolved after the dialog switched tickets would start displaying on the new ticket, where today it is stamped with the old id and stays hidden. Keep the parameter.

```ts
import { useEffect, useRef, useState } from 'react'

import { updateTicket } from './tickets'
import type { Ticket, TicketUpdate } from './domain'

export function useTicketCommit({
  ticket,
  onUpdated,
}: {
  ticket: Ticket | null
  onUpdated: (ticket: Ticket) => void
}): TicketCommit {
  const [errorFor, setErrorFor] = useState<{ ticketId: string; message: string } | null>(null)
  const ticketRef = useRef<Ticket | null>(ticket)
  useEffect(() => {
    ticketRef.current = ticket
  })
  const isMounted = useIsMounted()

  const error = ticket && errorFor?.ticketId === ticket.id ? errorFor.message : null

  // ... commit / applyServerRow, moved verbatim, with `mountedRef.current` replaced by
  // `isMounted()` and `setErrorFor({ ticketId, message })` reached through setError.

  return { commit, error, setError, clearError, applyServerRow, isMounted }
}
```

`useIsMounted` is the `mountedRef` pattern moved into its own hook, keeping the explicit set-true-on-mount that makes it correct under StrictMode's mount→unmount→mount:

```ts
/** True while this component instance is mounted. Read it after every `await` before
 *  touching state: a continuation that lands after unmount would otherwise resolve
 *  against a dead instance. The explicit true-on-mount (rather than relying on the
 *  initial value) keeps it correct under React StrictMode's mount→unmount→mount. */
export function useIsMounted(): () => boolean {
  const mountedRef = useRef(true)
  useEffect(() => {
    mountedRef.current = true
    return () => {
      mountedRef.current = false
    }
  }, [])
  return () => mountedRef.current
}
```

`setError` and `clearError`:

```ts
function setError(ticketId: string, message: string) {
  setErrorFor({ ticketId, message })
}
function clearError() {
  setErrorFor(null)
}
```

Note the one adjustment `error` needs: `ticket` is nullable here, so the guard becomes
`ticket && errorFor?.ticketId === ticket.id ? errorFor.message : null`. Behaviour is
identical — the dialog only reads `error` after its own `if (!ticket) return null`.
